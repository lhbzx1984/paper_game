# PaperQuest · 论文副本

把一篇英文 AI/ML 实证论文拆成「案件档案 + 四关调查 + 结案报告」的本地网页游戏。上传 PDF / TXT / Markdown，先读案件，再通过研究缺口、实验装配、结果判读、审稿对线四关检验自己是否真的读懂，最后带走一份阅读大纲与结案报告。原文抽屉提供「Markdown 阅读版」和「PDF 原件」两个视图，可导出 `.md`；已保存的上传案件会把 PDF 一并归档到本地资料库。

## 快速开始（Windows）

双击 `start.bat`。首次运行会自动创建 `.venv`、安装依赖，并打开 <http://127.0.0.1:5173>。以后再次双击即可启动。

手动启动：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
.venv\Scripts\python.exe app.py
```

没有 API Key 也能完整体验：默认 `MOCK_LLM=1`，上传任意论文会返回内置示例案件，试玩示例则始终可用。模拟模式只用于演示流程，不会解析你上传的内容。

## 接入真实论文解析

PaperQuest 调用任意兼容 OpenAI Chat Completions 的接口（OpenAI、DeepSeek、Moonshot、通义等）。

方式一：在页面右上角「模型设置」填写 Base URL、API Key、模型名，保存后会立即切换为真实解析。连接信息只保存在本机 Flask 进程内存里，不写入浏览器存储，也不会回传给前端；刷新或重启服务后需要重新填写。

方式二（持久化）：复制 `.env.example` 为 `.env`，填写：

```env
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini
MOCK_LLM=0
```

修改 `.env` 后重启服务生效。建议使用长上下文、指令遵循较好的模型；较强的模型更容易产出可回链的引文。`MOCK_LLM=1` 优先级高于真实连接，调试流程时可随时切回模拟模式。

## 一局是怎么跑的

上传后，服务端用 PyMuPDF 提取文字与章节，把标题、研究问题、缺口、方法配置、关键主张、结果、局限与术语整理成案件档案。真实模式会要求模型为每条关键主张和关卡给出 `evidence_quote`，服务端再拿引文与提取文本做字符串核验；一条都对不上会直接停止生成，低于 50% 会在案件页标注提示。

关卡随后在后台生成，案件页可以边读边等。四关分别是：

1. 缺口定位：从引言判断论文真正要填补的空白。
2. 实验装配：四类卡片各选一张，复原核心实验配置。
3. 结果侦探：判断哪条结论真正被数据支持，错误选项对应常见过度解读。
4. 审稿对线：先选最站得住脚的审稿意见，读作者回应后再做一次追问。

每题 25 分，总分 100。一次命中得满分，同一阶段第二次命中得 60%，展开解析得 20%；提示每次扣 3 分。审稿关拆成主问 15 分 + 追问 10 分，两段独立计分。答错会展示对应原文线索，第二次答错自动揭示解析。案件页始终可以打开原文抽屉：默认是排版后的「Markdown 阅读版」，命中的摘录会高亮并自动滚到对应位置；如果案件附有 PDF，还可以切到「PDF 原件」直接翻阅、在新窗口打开，或把阅读版导出为 `.md`。

结案页给出分数、四关判定、论证地图、逐关记录与原文定位。填写自己的审稿追问后，可以生成阅读大纲、复制大纲，或下载 Markdown 结案报告。报告包含每关作答记录、使用提示的情况、证据链、局限与你的审稿判断。

## 资料库与进度保存

四关全部生成后，案件页底部和游戏侧栏会出现「存入资料库」。保存的内容包括论文原文、案件档案、四关题目以及当前进度（每一关的作答、提示、得分、反思与阅读大纲）。如果案件来自 PDF 上传，保存时还会把原始 PDF 作为 BLOB 一并写入资料库，之后在资料库中重新打开仍可查看「PDF 原件」；示例案件使用内置的 `data/sample_paper.pdf`，模拟模式下的示例案件同理。没有归档 PDF 的旧记录或 TXT / Markdown 案件只显示 Markdown 阅读版，并在抽屉中标注「未附 PDF」。

保存之后进度会自动同步：每次作答、使用提示、进入下一关、修改反思或生成大纲，前端都会在短暂延迟后把最新进度写回数据库；切换案件或删除前会先把未完成的写入发出去。顶栏的「资料库」按钮会显示已存案件数量。

资料库按更新时间倒序排列，每张卡片显示状态（未开始 / 调查中 / 已结案）、得分、已完成关卡数、更新时间和来源。可以继续调查、删除，或从案件页再次保存以覆盖更新。删除需要二次确认；如果删除的是当前正在玩的案件，内存中的案件仍可继续阅读，但不会再自动同步，需要重新保存才会生成新记录。

数据存放在本机 `data/paperquest.db`（SQLite，首次启动自动创建），不会上传到任何服务器。PDF 原件也保存在这个文件里，单个 PDF 上限 25 MB，因此资料库文件会随归档的论文数量增长。同一篇论文按正文内容哈希去重：重复保存会更新原记录并保留已有进度，而不是新增一条。项目没有账号体系，资料库只对这台机器上的当前用户可见。

## 支持范围

- 输入：PDF（需要可提取文字，扫描版请先 OCR）、TXT、Markdown，单文件 25 MB 以内。
- 原文视图：Markdown 阅读版由提取文本重新排版，保留章节层级与段落；PDF 原件在示例案件、模拟模式和已归档 PDF 的上传案件中可用。
- 论文：英文 AI/ML 实证论文效果最好；其他领域也能跑，但题目质量取决于模型与论文结构。
- 未保存的案件只存在内存中，刷新页面会丢失；已保存的案件与进度写入本机 SQLite，可在资料库中继续或删除。
- 引文核验是普通字符串对齐，不是语义判断；报告与大纲用于辅助阅读，正式引用前请回到原始 PDF 复核。

## 目录

```
app.py                  Flask 服务与 API
storage.py              SQLite 资料库：保存、列表、读取、进度更新、删除、PDF 归档与读取
llm_client.py           OpenAI-compatible 调用、运行时配置
paper_utils.py          PDF 提取、章节切分、档案/关卡规范化、引文核验
prompts.py              案件档案与关卡生成提示词
data/                   示例论文、示例案件、示例关卡、测试 PDF；运行时生成 paperquest.db
static/                 单页前端（HTML / CSS / 原生 JS）
tests/                  测试 PDF 生成器与本地假模型服务
start.bat               Windows 一键启动
```

接口：`GET /api/status`、`GET /api/demo`、`POST /api/analyze`、`POST /api/generate`、`POST /api/config`、`POST /api/config/test`，以及资料库的 `GET /api/library`、`POST /api/library`、`GET /api/library/<id>`、`PATCH /api/library/<id>`、`DELETE /api/library/<id>`。PDF 相关接口为 `GET /api/demo/pdf` 和 `GET /api/library/<id>/pdf`（默认内联预览，加 `?download=1` 下载）；保存时 `POST /api/library` 既接受 JSON，也接受 `multipart/form-data`（`payload` JSON 字段 + `pdf` 文件字段）。

## 已知边界

- 没有账号、权限或云端同步，资料库属于本机单用户；换机器需自行拷贝 `data/paperquest.db`，归档的 PDF 也在这个文件里。
- 同一篇论文按内容哈希去重，重复保存会更新原记录并保留进度。模拟模式下所有上传内容相同，会命中同一条示例记录。
- 模拟模式下上传真实 PDF，案件内容与「PDF 原件」都来自示例论文，不读取你上传的 PDF 正文；要解析自己的论文需关闭 `MOCK_LLM` 并配置真实模型。
- 未保存的上传 PDF 用浏览器临时 Blob 地址预览，刷新或换设备后就没了；只有保存进资料库才会归档原件。
- 已经保存但没有 PDF 的旧记录（例如本次升级前保存的案件）只能看 Markdown 阅读版，不会自动补回 PDF；重新上传同一篇论文并保存可补上原件。
- 运行时模型配置不落盘，需要持久化请写 `.env`。
- 超长论文只把摘要式 digest（约 28k 字符）送给模型，正文仍保留在本地供原文定位。
- 题目生成依赖模型能力；若模型反复给出无法对齐的引文，服务会安全失败而不是伪造证据。
